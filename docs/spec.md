# 杉本研究室 備品管理アプリ 仕様書

## 1. 概要

### 1.1 目的

杉本研究室の備品の状況(誰が使用中か、どこにあるか など)を、誰でも一目で把握できるようにする。

### 1.2 コンセプト

- 備品ごとに「現在の状態(使用中・保管中など)」「使用者」「保管場所」を確認できる。
- ユーザーが手軽に状況を記録できることを重視する。記録の手間が大きいと運用が続かないため、操作数を少なくする。

## 2. システム構成

front / backend / database の3層構成とし、リポジトリはモノレポで管理する(front と backend を1つのリポジトリに同居させる)。

| 層       | 役割                        | 採用技術 |
| -------- | --------------------------- | -------- |
| front    | 画面表示・ユーザー操作      | React + Tailwind |
| backend  | データの受け渡し・処理・認証 | FastAPI  |
| database | データ管理                  | MongoDB  |

## 3. ページ構成

### 3.1 ページ一覧

閲覧操作は誰でも可能。データベースへの変更操作（備品登録、借用、返却、削除、ユーザー登録）の実行時には「合言葉（パスワード）」による認可が必要。一度成功するとブラウザに長期キャッシュ（約1年間有効）される。

| #   | ページ名             | パス(仮)       | 目的                                                           | 認可 (合言葉) |
| --- | -------------------- | -------------- | -------------------------------------------------------------- | ------------- |
| 1   | メイン画面           | `/`            | 備品の検索と、各ページ・QR コード読み取りへの入口              | 不要          |
| 2   | 備品登録画面         | `/items/new`   | 新しい備品を登録する                                           | 登録時に必要  |
| 3   | ログイン画面         | `/login`       | 登録済みのユーザーがログインする                               | 不要          |
| 4   | ユーザー登録画面     | `/users/new`   | 新しいユーザーを登録する                                       | 登録時に必要  |
| 5   | ユーザーページ       | `/users/:id`   | ユーザーの情報や、そのユーザーが使用中の備品を確認する         | 不要          |
| 6   | 棚の詳細ページ       | `/shelves/:id` | 棚の QR コードを読み取った際に開く。その棚にある備品を確認する | 不要          |
| 7   | アイテムの詳細ページ | `/items/:id`   | 備品の詳細と現在の状況を確認し、状況を記録する                 | 操作時に必要  |
| 8   | 全備品一覧画面       | `/items`       | 登録されている全備品を一覧で確認する                           | 不要          |

### 3.2 各ページ詳細

各ページは、1行の説明、パス、画面の概要図、要素の表の順に簡潔に記述する。画面遷移は、各ページの説明や表に含めて記載する。

## 4. データベース設計

データベース(MongoDB)には、次の4種類のデータを保存する。各データの項目(フィールド)は、今後決める。

| データ   | 内容                                                                     |
| -------- | ------------------------------------------------------------------------ |
| 備品     | 管理番号、品名、画像、詳細情報など。備品登録画面(3.2.2)で登録する        |
| ユーザー | 名前、学年。ユーザー登録画面(3.2.4)で登録する                            |
| 棚       | 棚(区画)の情報。メイン画面の棚の図と棚の詳細ページに使う                 |
| 使用履歴 | 誰がいつ備品を使用・返却したか。現在の状況と最後に使用した人の表示に使う |

## 5. 話し合い事項

### 全体

- 備品のジャンル(VR、グラボなど)を持たせるか。持たせる場合は、備品登録画面(3.2.2)での入力、全備品一覧画面(3.2.8)の一覧・メイン画面(3.2.1)の検索での絞り込み、データベースの備品データへの追加が必要になる。ジャンルの種類は固定にするか、自由に追加できるようにするか。
- 画面の言語(日本語のみか、英語との切り替えを付けるか)。

### 備品登録画面(3.2.2)

- 「詳細情報」に他の項目(メーカー・型番・購入日など)を足すか。
- 登録ボタンを押したあとの遷移先。

### メイン画面(3.2.1)

- QR ボタンを押したときの動作 -> QRコードリーダーを開くようにすればいいか？

### 棚の詳細ページ(3.2.6)

- 「棚の位置」の表し方(メイン画面の棚の図で該当区画を強調する形でよいか。文字での場所の説明も付けるか)。
- リストの各行に、状態以外で表示する項目。

### 全備品一覧画面(3.2.8)

- リストの各行に、品名・管理番号・状態以外で表示する項目(使用者、保管場所など)。
- ダウンロードする情報の範囲(全項目か、画像を含めるか)。

### アイテムの詳細ページ(3.2.7)

- 「詳細情報」に何を表示するか(棚の位置、最後に使用した人のほか、備品登録画面の詳細情報など)。棚の位置の表し方(文字で「A-1」のように示すか、棚の図で強調するか)。
- 使用ボタン・返却ボタンの動作条件(使用中のときは使用ボタンを押せない、など。返却できるのは使用者本人だけか)。
- 使用・返却のあとの画面の動き(同じ画面で状況を更新するか)。
- 「最後に使用した人」の履歴を、最後の1人だけでなく一覧として残すか。
- 状態の区分は「使用中」「貸出可能」の2つだけでよいか(保管中・修理中などを足すか)。

### ログイン画面(3.2.3)・ユーザー登録画面(3.2.4)

- 学年のドロップダウンの選択肢(例: B1〜B4、M1・M2、D1〜D3、教員など)。
- 登録ボタン・ログインボタンを押したあとの遷移先。
- ログインは名前と学年だけで成立する(パスワードなし)。同名・同学年のユーザーをどう区別するか。
